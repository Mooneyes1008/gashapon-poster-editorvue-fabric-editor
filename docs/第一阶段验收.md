浏览器实测流程：

1. 上传透明 PNG、JPEG 和 WebP → 共享库显示三张资产。
2. 点击加入 → 鼠标拖动、角点等比缩放、旋转 23°、复制和替换；确认替换保留角度。
3. 文字工具 → 点击画布 → 修改内容、内置字体、字号、描边、阴影、字距；双击画布文字再次编辑。
4. 图层重命名、显示/隐藏、锁定/解锁、拖动排序 → 撤销 → 重做。
5. 保存 → 刷新 → 检查图片、布局和文字属性保持。
6. PNG 导出 → 检查实际文件为 **1800×2400**；有选框和无选框时导出的文件逐字节一致。
7. 导出完整项目 → 新建空白页 → 重新导入 → 比较项目内容、资产及布局完全相同。
8. 分别添加 3/4/5/6 款模板 → 检查产品位及款名数量 → 替换产品位 → 删除对象仍保留源资产 → 撤销恢复。
9. 测试 4:3、3:4、自定义尺寸，确认没有改变另一页面。
10. 导入包含外部图片地址的无效文件 → 明确报错且原项目不变。
11. 查看素材服务不可用提示及 AI 未接入状态。

## 复跑浏览器验收

先在一个终端运行 `pnpm dev --strictPort`。另一个终端安装独立验收工具（不修改项目依赖/锁文件）：

```sh
npm install --prefix /tmp/poster-browser-tools --no-package-lock playwright-core@1.56.1
PLAYWRIGHT_MODULE_PATH=/tmp/poster-browser-tools/node_modules CHROMIUM_PATH=/usr/bin/chromium node scripts/phase-one-smoke.cjs
```

上述是 Linux 命令，需要 Chromium 已安装；其它系统请将 `CHROMIUM_PATH` 改为实际浏览器可执行文件，并使用该系统设置环境变量的语法。结果默认写入 `/tmp/gashapon-acceptance`。`POSTER_URL` 可指定测试站点，`POSTER_ARTIFACTS` 可更改输出目录。脚本的图片是运行时生成的测试夹具，不含在线素材。

云环境安装与启动说明已另存配置草稿；安装脚本只准备 Node/pnpm 和锁文件依赖，不启动长期服务。修改后的配置需再次保存/发布才成为后续环境版本。当前分支的本地 Git 提交不等于已经推送远程，也不等于新任务已检出该分支。
